# Finding Jobs

面向自动化、机器人、具身智能、人工智能、计算机、电子信息和工业工程等专业学生的岗位方向决策工具。

它把公司、岗位方向、技能和公开信息整理成一个可搜索、可筛选、可比较的前端网站，帮助用户先判断适合关注哪些方向，再去核对公司的官方信息。公司覆盖已从北京扩展到上海、深圳、杭州、苏州、南京等城市，可通过城市筛选自由切换。

## 这个站和其他招聘内容的区别

- **诚实的数据标注**：每家公司都有 `verificationStatus`（已公开核验 / 部分核验 / 待核验）和 `lastVerifiedAt`，核验过期会在界面上明示。宁可标注"待核验"，不编造岗位事实——在假岗位满天飞的招聘内容里，这是本站的第一卖点。
- **只放官方入口**：投递链接全部指向公司官网招聘页等公开渠道，每条入口单独记录核验时间；不接招聘平台账号，不代投，不抓取登录后数据。
- **岗位方向画像，不是职位列表**：每个方向有技术深度、沟通强度、出差强度、项目协调、应届生友好度五个维度的量化画像和典型挑战说明，回答"我适合做什么"而不只是"哪里在招人"。
- **决策工具链**：快速选岗（5 个偏好问题收敛到 3~5 个候选）→ 候选对比（最多 5 个方向横向比较）→ 公司雷达（按梯队/职能/技能筛选）→ 官方入口核验，一条完整的决策路径。
- **轻、快、免费**：纯静态单页应用，无后端、无数据库、无登录、无广告、无埋点；筛选状态实时同步 URL，任何视图都可以直接分享链接。

## 项目定位

本项目是"岗位方向导航"，不是实时招聘数据库。

- 公司与岗位的关联表示业务方向适配，不代表公司当前正在招聘。
- 招聘入口、岗位名称、工作地点和招聘批次，必须以公司官方页面为准。
- 项目不接入招聘平台账号，不自动投递，不抓取登录后的职位数据。
- 数据由本地 TypeScript 文件人工维护，并保留来源和核验状态。

## 主要功能

- 公司雷达：按城市、梯队、类型、岗位方向和核心技能筛选。
- 岗位方向导航：覆盖研发、产品、方案、技术服务、交付、测试、制造、供应链、销售和运营等方向。
- 缩写搜索：支持 FAE、FSE、NPI、SQE、CQE、PMM、CSM、SLAM、VLA 等精确匹配；PM、SE、AE 会先给出消歧选项。
- 快速选岗：通过 5 个实际偏好问题，把岗位方向收敛到 3～5 个候选结果。
- 候选方向：最多保存 5 个正式职业方向，并通过 URL 分享和恢复。
- 横向比较：比较职能、轨道、工作阶段、交付物、技术深度、沟通强度、出差强度、核心技能和典型挑战。
- 技能矩阵：59 项技能按 7 个能力域分组，低频专业技能默认收起。
- 公司关联分级：岗位与公司关联分为 `core`、`adjacent`、`possible`，并显示判断理由。
- 链接核验：检查公司官网、公开来源和已核验的申请入口是否可访问。

## 快速开始

环境要求：Node.js 20.19+ 或 22.12+（Vite 7 要求；`npm run check:links` 需 Node 22.18+ 以支持 TS 类型剥离）。

```bash
npm install
npm run dev
```

开发服务器启动后，打开终端显示的本地地址即可访问。

生产构建：

```bash
npm run build
```

构建产物位于 `dist/`，可部署到 Vercel、静态服务器或其他支持单页应用的托管服务。

## 常用命令

```bash
# 运行全部测试
npm test

# 构建生产版本
npm run build

# 检查公开链接
npm run check:links

# 检查生产依赖漏洞
npm audit --omit=dev
```

提交代码前，至少运行 `npm test`、`npm run build` 和 `npm run check:links`。

## 数据维护

### 公司数据

公司数据位于 [`src/data/companies.ts`](src/data/companies.ts)，类型定义位于 [`src/types.ts`](src/types.ts)。

新增或更新公司时，应补齐：

- 公司名称、英文名称和公司类型
- 城市布局 `cities`（每项含 `city` 与 `presence`：总部 / 研发中心 / 主要岗位 / 创新平台 / 待核验）
- 人工维护的公司核心技能 `recommendedSkills`
- 推荐理由、风险提示和项目建议
- 已核验的 `sourceLinks`
- `verificationStatus` 和 `lastVerifiedAt`
- 已确认的 `applicationEntries`

公司核心技能只能来自人工维护字段，不会自动吸收关联岗位的技能。

### 岗位数据

岗位方向位于 [`src/data/jobRoles.ts`](src/data/jobRoles.ts)，岗位与公司的关联位于 [`src/data/companyRoleFits.ts`](src/data/companyRoleFits.ts)。

每个岗位应维护：

- `functionType`：职能分类
- `track`：岗位轨道
- `roleKind`：正式职业方向或应届生综合入口
- 岗位描述、常见标题、主要职责和典型挑战
- 适合专业、适合人群和自动化专业视角
- 必备技能、加分技能和推荐项目
- 技术深度、沟通强度、出差强度、协调强度和应届生友好度
- 高重叠岗位的工作阶段、主要交付物和责任边界

公司岗位关联必须使用真实存在的公司 ID 和岗位 ID，等级只能是：

- `core`：公司的核心业务直接需要该方向
- `adjacent`：与公司业务有较强合理关系的配套方向
- `possible`：可能相关，仅用于扩展检索

每条关联都必须填写 `reason`，且不能写成“公司正在招聘”的事实陈述。

### 技能数据

技能定义位于 [`src/data/skills.ts`](src/data/skills.ts)。每项技能只能属于一个主分组：

1. 软件与工程基础
2. 机器人算法与仿真
3. 产品、方案与项目
4. 技术服务与现场
5. 测试与质量
6. 制造与供应链
7. 销售、市场与运营

## 页面状态与分享

候选岗位、岗位筛选、岗位轨道和快速选岗偏好会写入 URL Query，支持：

- 刷新后恢复
- 分享链接恢复
- 浏览器前进和后退
- 自动忽略非法岗位 ID
- 候选岗位最多 5 个

临时的展开/折叠状态不会写入 URL。

## 验证与边界

当前项目使用自动化测试验证数据完整性、缩写搜索、岗位关联、技能分组、快速选岗、候选恢复、比较维度和组件交互。

链接检查只验证 URL 是否可访问，不代表对应岗位当前仍在招聘，也不代表页面内容一定与岗位方向完全一致。最终投递前，请再次查看公司官方招聘页面。
