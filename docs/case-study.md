# Finding Jobs 案例复盘

## 一句话说明

Finding Jobs 是一个面向自动化、机器人、具身智能和相关专业学生的岗位方向决策工具。它不复制招聘平台的职位列表，而是把分散的公开信息整理为可核验、可比较、可分享的决策路径。

## 要解决的问题

学生通常先看到公司名或岗位名，却难以判断三个问题：这个方向实际做什么、自己是否适合、下一步应该补什么能力。公开招聘链接还会过期，单纯堆链接会很快失去可信度。

项目因此把目标限定为“帮助用户确定值得继续研究的方向”，而不是承诺实时职位、代投或录用结果。

## 我的工作

该仓库由单一贡献者完成，工作范围包括：

- 定义公司、岗位、技能、城市和关联关系的数据结构；
- 设计快速选岗、候选对比、公司雷达和官方入口核验流程；
- 实现 React 前端、URL 状态同步、筛选搜索和可访问性交互；
- 建立数据完整性测试、组件测试、生产构建和定时链接检查；
- 为每条判断保留来源、核验时间、可信状态和使用边界。

## 关键设计决定

### 1. 岗位方向优先，而不是职位数量优先

产品首先解释岗位的职责、工作阶段、交付物、技术深度、沟通强度和典型挑战。公司入口放在方向判断之后，避免把“公司可能涉及某方向”误写成“公司正在招聘”。

### 2. 把不确定性建模成数据

公司记录包含 `verificationStatus`、`lastVerifiedAt` 和公开来源。岗位与公司的关联分为 `core`、`adjacent`、`possible`，并要求写明理由。未知信息保留为待核验，不用推测补齐。

### 3. 外部链接失败不等于死链

链接检查把明确的 404、410 和 DNS 不存在判为失败；登录墙、限流、服务端错误、超时、TLS/WAF 和重定向异常判为警告。原因是自动检查器被拦截只能证明“本次无法验证”，不能证明浏览器用户一定无法访问。URL 格式由独立的数据完整性测试负责。

### 4. 所有可分享状态写入 URL

筛选条件、候选方向和快速选岗偏好写入 URL Query，支持刷新恢复、前进后退和直接分享；临时展开状态不写入 URL，避免产生无意义链接。

## 证据

![Finding Jobs 线上首页](images/overview.png)

截至 2026-08-31：

- 线上版本公开展示 45 家公司、29 个岗位方向和 25 个官方投递入口；
- 本地验证为 98 项自动化测试通过，生产构建通过；
- 链接检查覆盖 90 个唯一公开地址，并输出可审计的 JSON 报告；
- GitHub Actions 在提交时运行测试和构建，每周运行公开链接检查。

这些数字只描述当日仓库和公开数据状态，不代表招聘规模、用户数量或商业成果。

## 当前边界

- 数据由公开来源人工维护，不是实时招聘数据库；
- 链接可达不代表职位仍开放，投递前必须再次查看公司官方页面；
- 岗位画像是结构化决策辅助，不替代个人经历、地点和机会成本判断；
- 项目没有登录、代投、简历存储、广告和用户追踪。

## 如何验证

```bash
npm ci
npm test
npm run build
npm run check:links
```

测试验证内部逻辑，链接检查验证当前公开入口；两者都通过，才能说明本次版本具备可发布条件。
